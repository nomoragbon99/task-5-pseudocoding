================================================================================
PART A1: OWN FUNCTION 2 - ADMIN TOKEN AUTHENTICATION (CONSTANT-TIME COMPARE)
================================================================================

FUNCTION verifyAdminToken
INPUTS:
  - headerValue: Any type, the raw header value received from the HTTP request (e.g., "x-admin-token" or "Authorization")
  - expectedToken: String, the secret administrator token configured on the server
OUTPUT:
  - isAuthorized: Boolean, true if the provided token matches the expected secret, false otherwise
SIDE EFFECTS:
  - NONE
FAILS WHEN:
  - expectedToken is not text or is empty (server configuration defect)
  - Crypto subsystem error occurs during hash computation (CALL cryptographic digest (may fail))

--------------------------------------------------------------------------------
PSEUDOCODE BODY
--------------------------------------------------------------------------------

1. Validate the server configuration for the expected secret token.
   IF expectedToken is not text OR expectedToken contains only blank spaces THEN
     RAISE ERROR "Expected admin token must be a configured non-empty string"
   OTHERWISE continue.

2. Verify that the incoming header value is a valid text string.
   IF headerValue is not text THEN
     RETURN FALSE
   OTHERWISE continue.

3. Clean leading and trailing blank spaces from headerValue, storing the result as rawToken.

4. Check whether rawToken begins with the standard authorization scheme prefix "Bearer ".
   IF rawToken begins with "Bearer " THEN
     Remove the first seven characters ("Bearer ") from rawToken, strip any remaining outer spaces, and store the remainder as cleanedToken
   OTHERWISE
     Store rawToken as cleanedToken
   END IF

5. Verify that the cleaned token is not empty.
   IF cleanedToken is empty THEN
     RETURN FALSE
   OTHERWISE continue.

6. Compute the cryptographic SHA-256 digest of cleanedToken to yield a fixed 32-byte representation.
   CALL cryptographic digest (may fail) to generate tokenDigest.

7. Compute the cryptographic SHA-256 digest of expectedToken to yield a fixed 32-byte representation.
   CALL cryptographic digest (may fail) to generate expectedDigest.

8. Perform a constant-time byte-by-byte comparison between tokenDigest and expectedDigest to prevent side-channel timing attacks.
   CALL timing-safe comparison on tokenDigest and expectedDigest, storing the boolean outcome as matchResult.

9. RETURN matchResult.
