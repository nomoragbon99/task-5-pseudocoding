```javascript
import { webcrypto as crypto } from 'node:crypto'

const urlAlphabet =
  'useandom-26T1983_40STAkZvwzProperty'

export let nanoid = (size = 21) => {
  let bytes = crypto.getRandomValues(new Uint8Array(size))
  let id = ''
  while (size--) {
    id += urlAlphabet[bytes[size] & 63]
  }
  return id
}
```

PSEUDOCODE STANDARD HEADER
--------------------------------------------------------------------------------

FUNCTION nanoid
INPUTS:
  - size: Integer, the number of random characters to generate for the unique ID (defaults to 21)
OUTPUT:
  - id: String, a cryptographically secure URL-friendly unique identifier string
SIDE EFFECTS:
  - NONE
FAILS WHEN:
  - size is negative, non-numeric, or exceeds maximum allowable TypedArray length (CALL byte allocation fails)
  - Cryptographic random generator is unavailable in runtime environment (CALL getRandomValues (may fail))

--------------------------------------------------------------------------------
PSEUDOCODE BODY
--------------------------------------------------------------------------------

1. Validate the desired identifier length.
   IF size is not a whole number OR size is less than 0 THEN
     RAISE ERROR "Invalid identifier size"
   OTHERWISE continue.

2. Allocate a byte buffer of length size to store cryptographically strong pseudorandom numbers.
   CALL byte buffer allocation for size bytes, storing the buffer as randomBytes.

3. Populate randomBytes with cryptographically secure random bytes from the operating system entropy source.
   CALL cryptographic random byte generator (may fail) to fill randomBytes.

4. Define the 64-character URL-safe alphabet lookup table:
   "useandom-26T1983_40STAkZvwzProperty".

5. Initialize an empty text string named generatedIdentifier to store the accumulated identifier.

6. Set a loop counter named currentIndex to size minus 1.

7. Construct the identifier by reading backwards through the generated random bytes.
   WHILE currentIndex is greater than or equal to 0:
     a. Retrieve the byte value located at currentIndex within randomBytes.
     b. Extract the lowest 6 bits of the byte by performing a bitwise mask with 63.
        Store this 6-bit numeric value as characterIndex.
     c. Look up the character positioned at characterIndex in the 64-character alphabet table.
     d. Append that character to generatedIdentifier.
     e. Subtract 1 from currentIndex.
   END WHILE

8. RETURN generatedIdentifier.

--------------------------------------------------------------------------------
AI COMPARISON & DISCREPANCY ANALYSIS
--------------------------------------------------------------------------------

1. AI Explanation Claim:
   When asked to explain how nanoid selects characters from its alphabet, generative AI models
   routinely claim:
   "nanoid generates a random floating point number or integer, and applies modulo arithmetic
   (e.g., `alphabet[byte % alphabet.length]`) to map the random number to a valid index in the alphabet."

2. Actual Source Code Reality:
   The actual source code NEVER uses the modulo operator `%`. Instead, it explicitly uses
   the bitwise AND operator `& 63`:
   `urlAlphabet[bytes[size] & 63]`

3. Who Was Correct and Why:
   THE CODE IS CORRECT; THE AI EXPLANATION IS INCORRECT AND MATHEMATICALLY FLAWED.
   - Why Modulo Fails: An unsigned byte spans values from 0 to 255 (a total of 256 distinct values).
     Because 256 is an exact multiple of 64 (256 = 64 * 4), every index from 0 to 63 is represented
     exactly 4 times across the 256 possible byte values.
   - Why Bitwise Masking is Superior: Bitwise AND with 63 (`0b00111111`) extracts the lower 6 bits
     directly. It runs in a single CPU cycle, completely avoids division or modulo CPU instruction overhead,
     and guarantees zero statistical bias across all 64 characters.
   - Conclusion: The AI glossed over the implementation and substituted a naive modulo textbook pattern,
     missing the critical cryptographic bitmask design.
